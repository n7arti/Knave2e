Процесс сборки системы правил

Система — один JSON-документ, прошедший RuleSystemSchema и полный loader pipeline. Автор не пишет JavaScript; манифест не получает браузерный или сетевой API. Встроенная и пользовательская система имеют один контракт: место хранения не даёт скрытых возможностей. Всё ниже следует из этого.

1. Комплект и старшинство

Читать в этом порядке; при расхождении побеждает верхний.

Файл Роль
живая схема загрузчика стола побеждает всё: манифест, который её не проходит, комната не принимает
manifest.html справочник по каждому полю манифеста
action-dsl-reference.json машинный контракт действий и шагов
glossary.json термины действий + слой authoring
дайджест ключей встроенных систем в master-pack.json образец формы, не источник правил
минимальный манифест (раздел «Минимальный манифест» в manifest.html) валидный манифест на один экран — точка старта
раздел «Язык листа» в manifest.html почему DSL устроен так — когда спорно
эта страница процесс, порядок, проверки, диагностика

Поле, которого нет в схеме, не выдумывается. Нельзя выразить — так и сказать мастеру, предложив ближайшее выразимое.

Комплект для модели: эта страница, manifest.html, action-dsl-reference.json, glossary.json и master-pack.json.

2. Два канала

UI /systems — десять страниц (см. таблицу ниже), сохранение по одной, после Save полная проверка, предпросмотр черновика, тестовый персонаж.

MCP / REST с PAT — systems_list, systems_get, systems_create, systems_update, systems_patch_definition, systems_delete, systems_restore, systems_clone, systems_members_{list,add,set_role,remove}. Подключение — «Подключение агента» в настройках аккаунта. Нужны capability agent.api.assets и scope systems:read / systems:write.

Ответ Значит
PLAN_FORBIDDEN capability отозвана или тариф понижен — канал закрыт весь
SCOPE_FORBIDDEN токену не выдан scope
PAT_ENDPOINT_FORBIDDEN маршрут вне матрицы: комнаты, сцены, аккаунты, биллинг недоступны принципиально
RATE_LIMITED 600 запросов в минуту на токен

Через канал нет комнат и сцен: подготовить данные можно, применить — нет, и это говорится прямо. После потерянного ответа на запись не повторять вслепую — идемпотентности нет; сначала systems_get.

3. Инварианты, которые ломают чаще всего

  • definition — целое. systems_patch_definition заменяет манифест полностью. Всегда: GET → правка только затронутых путей → PATCH целого → GET для сверки. Неизвестные ключи сохраняются как есть.
  • id системы — долговечная ссылка: за него держатся комнаты, токены, сохранённые данные. Не менять id у системы, которая стояла на столе. Название — свободно.
  • Система — одна на комнату, все столы: space['rule_system_link'] в пространстве комнаты (Yjs, getDomainMap('room')) — источник истины; rooms.rule_system_id в БД — сид новой комнаты и проекция пространства. Привязывать через patch_state / patchState мастером или ассистентом; копия в world стола — пережиток до 15.10.2026, её никто не читает.
  • Ключи полей — имена переменных во всех формулах. Переименовал в одном месте — проверь остальные; редактор после Save покажет разрывы, API — нет.
  • Новая система — приватная. Видимость, участников, публикацию менять только по явной просьбе. Встроенная не правится — только systems_clone.

4. Порядок сборки

Зависимости направлены; иначе reference-стадия валит документ на полпути.

  1. Идентичность — schemaVersion, стабильный id, name, version, description.
  2. fieldGroups — данные персонажа. Ключи полей = переменные формул.
  3. dataScopes — кто видит и правит. Поле без области — открыто всем.
  4. resources — пары current/max поверх уже объявленных полей. У ресурса, который тратят заклинания, приёмы и ход, — род category и круг rank (ячейки всех кругов и ячейка договора — один род spell_slot), а словарь resourceCategories даёт роду подпись и знак; роды action, bonus_action, reaction, movement в словаре включают маркер хода на карточке. Без рода реакция и чип траты ресурс не узнают.
  5. derivedFields — чистые формулы, без случайности.
  6. autoModifiers — метки на токене из тех же данных.
  7. conditions — состояния, на которые сошлются действия.
  8. actions (+ actionGroups, bonusCategories).
  9. sheetVariants — раскладка. Layout не объявляет данные, только размещает.
  10. vision, entryConventions, catalogs, equipment — по необходимости.
  11. editorMeta._previewSeed — данные предпросмотра; комната их не читает.
  12. migrations — только с подъёмом version и несовместимыми данными.

Старт: rule-system-minimal.json для новой системы, systems_clone встроенной для большой — и вычитание лишнего.

5. Загрузка системы одним файлом

Готовый манифест можно передать мастеру обычным .json-файлом: один объект RuleSystemSchema, без обёртки { definition: ... }. На /systems мастер создаёт или открывает свою систему и нажимает «Загрузить JSON» в шапке. Для встроенной или чужой системы сначала нужна своя копия.

Файл проходит полный pipeline. Блокирующие ошибки запрещают сохранение; сломанные ссылки/формулы и предупреждения показываются перед записью. Можно открыть предпросмотр листа. «Заменить систему» записывает весь манифест, включая имя и удаление отсутствующих разделов; владельцы и доступ не меняются. При ошибке сохранения файл остаётся в диалоге для повтора. Перед загрузкой нужно сохранить или отменить черновики всех страниц.

«Скачать JSON» выгружает сохранённый манифест одним файлом, без черновиков. Авторские $comment и editorMeta сохраняются при загрузке и скачивании.

6. Десять документов редактора

Мастер видит манифест страницами /systems; говорить с ним на этом языке. Сохранение страницы заменяет только её ключи.

Страница Ключи
Система identity, version, distanceMethod, dicePanel, fct
Поля fieldGroups, dataScopes
Ресурсы resources
Вычисляемые derivedFields, autoModifiers
Действия actions, actionGroups, conditions, bonusCategories
Листы sheetVariants, резервный sheetLayout
Зрение vision
Записи entryConventions, noteFolders
Справочники catalogs, timeEvents, slotLists, migrations
Прочее всё остальное: abilities, combatPresentation, critRule, initiative, itemRules, damageCascades, stateRules, equipment, fx, editorMeta, устаревшие слоты

Единый список слотов отдаёт systems_get в definition.documents.

7. Четыре диалекта — половина всех ошибок

Прежде чем чинить «валидную формулу, которая даёт ноль», определить диалект.

  1. Formula / Predicate — derivedFields, условия. Детерминированный, тотальный: нет циклов, рекурсии, функций. floor((str - 10) / 2), hp <= 0, contains('traits', 'flying'). Синтаксис — внутренние заметки (не опубликованы).
  2. Dice — roll-шаги, rollFormula: 1d20 + str_mod, 4d6kh3, 2d20kl1. Функции счётного вычислителя сюда не переносятся.
  3. Action DSL — шаги roll, save, damage, effect, timedEffect, modifyField, consumeResource, restoreResource, prompt, branch, chat, capability. Канон — action-dsl-reference.json.
  4. Sheet layout — дерево закрытых узлов. Новый тип узла — PR в ядро.

Шаблоны отображения ({name}, {if hp < max_hp/2 then … else …}) — внутренние заметки (не опубликованы); влияют только на показ.

8. Рецепты

Вертикальный срез — поле → derived → показ → действие, которое тратит:

{ "key": "power", "type": "number", "default": 10,
  "derivedKey": "power_mod", "derivedFormat": "{v}",
  "rollFormula": "1d20 + power_mod" }

{ "key": "power_mod", "formula": "floor((power - 10) / 2)" }

derivedFormat — {v}: лист сам ставит знак числу, +{v} даст «++3».

Ресурс — сначала поля focus, focus_max, затем:

{ "key": "focus", "currentKey": "focus", "maxKey": "focus_max",
  "recharge": "short-rest", "visibleTo": "all", "displayIn": ["sheet"] }

На листе появится только через узел resourceBar в раскладке.

Действие, которое может не состояться — расход первым шагом:

{ "id": "power-check", "usableBy": "owner", "steps": [
  { "type": "consumeResource", "resourceId": "focus", "amount": "1" },
  { "type": "roll", "formula": "1d20 + power_mod", "captureAs": "result" },
  { "type": "chat", "text": { "ru": "Проверка: {result}" } } ] }

Входные параметры — только шаг prompt; собирается до первого изменения состояния.

Два листа — sheetVariants с defaultFor: "player" / "creature". Приоритет: явный выбор на токене → autoWhen → defaultFor → резервный sheetLayout. Резерв — не третий вариант; заводить, когда непокрытые токены реальны.

Панель кубов — dicePanel на «Системе»; формулы проверяются при загрузке; hidden: true, если панель не нужна. Справка — manifest.html § «Панель кубов».

Подъём версии — version вверх и migrations; данные сыгранных комнат живут дольше манифеста, молчаливое переименование ключа их стирает.

9. Проверки

Pipeline из восьми стадий: parse → zod → overlay → reference → formula → scope → dag → hook. Любая ошибка — отказ комнаты.

  • reference — ссылка на несуществующий groupId, resourceKey, resourceId, conditionId, catalog, vision_profile_id;
  • formula — переменная не среди полей и derived;
  • scope — поле раздаёт данные шире, чем разрешает dataScopes;
  • dag — цикл в derived;
  • hook — legacy; в новой системе не используется.

Редактор гоняет полный pipeline после каждого Save и показывает ошибки с привязкой к документу и строке; API — нет: через канал сверять systems_get после записи. Ответ на запись — не доказательство.

Предупреждения (комната терпит, автор должен знать): устаревшие слоты hooks / sheetHTML / sheetTemplate; ключи _previewSeed.systemData, под которые нет поля.

10. Диагностика

Симптом Причина в девяти случаях из десяти
Формула «валидна», но 0 перепутан диалект: dice-функция в derived или наоборот
Derived не меняется опечатка в ключе; переменная не объявлена
Действия нет у игрока usableBy не owner либо поле закрыто dataScopes
Игрок видит скрытое chat/prompt подставляет ключ вне его области
Предпросмотр показывает старое режим «Сохранённое» или черновик не проходит проверку страницы
«++3» на листе derivedFormat: "+{v}" — лист ставит знак сам
Не тот вариант листа явный выбор на токене сильнее autoWhen и defaultFor
Зрение «работает» у мастера мастерская сцена ничего не доказывает — смотреть видом игрока
После перезагрузки поехали значения подняли version без migrations
Токены потеряли данные сменили id системы или ключ поля без миграции
Комната не подключает ошибка pipeline; в редакторе — красная панель под футером

11. Политики

  • Работать с той системой, которую назвал мастер; при неясности — scope=mine и спросить. myRole проверять: общий доступ ≠ право переписывать.
  • Сохранять неизвестные ключи; не выдумывать systemData, URL медиа, узлы layout.
  • Перед массовой записью — назвать план и количества.
  • Спрашивать перед: удалением, публичной видимостью, составом участников, переименованием любого id, за который могут держаться токены.
  • Каждая выдача заканчивается списком допущений и непроверенных мест.

12. Чего выразить нельзя

Честное «нельзя» дешевле трёх обходов: циклы, рекурсия, функции, JS-хуки как escape-hatch; новые типы узлов раскладки и шагов; комнаты, сцены, токены, файлы через канал; программируемая инициатива (внутренние заметки (не опубликованы) о границах DSL).

13. Готово — это когда

  • полный pipeline без ошибок; панель предупреждений понята;
  • в предпросмотре — обе темы, оба языка, Master / Owner / Other, каждый вариант;
  • на столе: Owner правит только разрешённое, Other не видит скрытого ни в листе, ни в тексте действия или чата;
  • действие различает нехватку ресурса, промах, успешный save, разные цели;
  • после перезагрузки значения не меняются сами;
  • мастеру перечислены: id системы, что изменено, что не закрыто.
