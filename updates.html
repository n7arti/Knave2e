У комплекта публичных гайдов есть собственная версия. Она объединяет документацию агента, Action DSL, глоссарий и практические инструкции. Это не версия API, не версия игровой системы и не идентификатор сборки клиента. Доступ к этим документам публичный, токен для их чтения не нужен.

1. Что проверять агенту

  • version.json — небольшой маркер доступного выпуска: schemaVersion, version, manifest.url, manifest.sha256, instructions.
  • release.json — версия, накопительная история releases и перечень documents с URL и SHA-256 содержимого каждого документа.
  • Эта страница — правила обновления и человекочитаемый журнал, собранный из тех же записей, что машинный манифест.

Версия имеет вид MAJOR.MINOR.PATCH. Major меняется при несовместимом изменении документированного способа работы; minor — при добавлении совместимых возможностей; patch — при исправлении или уточнении. Даже уточнение может потребовать изменения поведения, поэтому читайте agentAction во всех новых записях. Номера сравниваются по трём числам, не как строки.

Номер относится ко всему комплекту; точную редакцию отдельного документа определяет его SHA-256. История неизменяема: исправление старой инструкции оформляется новым выпуском. Старые тексты не раздаются по отдельным URL: журнал хранит историю изменений, текущие URL — действующие инструкции.

2. Когда проверять

При первом подключении, перед каждой новой задачей, после обнаруженного деплоя/обновления клиента и перед записью после паузы. Во время длительной непрерывной работы разумно проверять раз в пять минут и на границе очередного пакета изменений; не нужно опрашивать файл перед каждым чтением.

Запросите маркер с повторной проверкой кеша (Cache-Control: no-cache у HTTP клиента либо cache: "no-store" у fetch). Серверный маркер также отдаётся с запретом хранения после применения соответствующей конфигурации сервера. Если номер и хеш манифеста совпадают с принятыми, документы можно не загружать заново. Не посылайте секреты подключения на адреса документации.

Это протокол, который должен выполнять агент. Само наличие файлов не доставляет push-сообщение и не меняет память отключённого ассистента.

3. Порядок принятия нового выпуска

  1. Прочитайте version.json, проверьте поддерживаемый schemaVersion (сейчас 1).
  2. Прочитайте manifest.url на том же сайте. Вычислите SHA-256 байтов тела ответа после HTTP-декодирования; не пересериализуйте JSON перед вычислением. Хеш должен совпадать с manifest.sha256, версия — с маркером.
  3. Если сохранённой версии нет, прочитайте полные документы для своей задачи по маршруту discovery. Не пытайтесь восстановить контракт только по короткому журналу.
  4. Если версия известна и присутствует в истории, прочитайте все выпуски после неё в порядке возрастания. В каждом блоке есть kind, summary, agentAction, documents. Выполните указанные изменения инструкций и перечитайте затронутые документы, относящиеся к вашим операциям.
  5. Сверьте SHA-256 прочитанных документов с documents. При изменении хеша используемого документа перечитайте его, даже если краткая заметка не перечисляет каждый изменённый абзац. Версию старого документа нельзя определять лишь по его заголовку или дате.
  6. Проверьте живой канал: при работе с комнатой заново получите get_schema, при работе с материалами — актуальные данные/права. Гайд не добавляет команды старой открытой вкладке мастера и не заменяет фактическую схему.
  7. Перечитайте маркер. Если версия или хеш изменились за время чтения, повторите сбор комплекта. При согласованном наборе сохраните принятую версию, хеш манифеста и хеши используемых документов в паспорте задачи.
  8. Перед следующей записью перепроверьте ранее подготовленный JSON/план по изменившимся правилам. Изменения гайда не расширяют поручение пользователя и не выдают дополнительных полномочий.

Если заметка противоречит полному документу или живому каналу, остановите зависимую операцию и сообщите конкретное расхождение. Не считайте более новый текст разрешением отправить отсутствующий параметр.

4. Деплой, откат и незнакомая версия

Публичные страницы обновляются вместе с клиентом. Маркер версии гайдов выкладывается после синхронизации файлов и успешных проверок готовности деплоя. Во время замены файлов старый маркер может временно указывать на предыдущие хеши: несовпадение означает, что комплект ещё нельзя принять.

При несовпадении хешей или временной недоступности повторите чтение с ограниченной задержкой. До получения согласованного комплекта не выполняйте записи по смешанным инструкциям. Если проблема сохраняется, сообщите её пользователю; не повторяйте игровые мутации для проверки связи.

При откате опубликованный номер может стать меньше сохранённого. Если предыдущего номера нет в истории, сменился сайт, пришёл неизвестный формат или та же версия получила другой хеш, не вычисляйте частичную миграцию: заново прочитайте актуальные документы для задачи и проверьте канал. Для одинаковой версии с другим хешем сначала исключите незавершённую выкладку; такое изменение считается нарушением неизменяемости выпуска.

Если /agent-guide/version.json отсутствует или вместо JSON вернулся HTML, сайт ещё не поддерживает этот протокол. Прочитайте доступные документы и живую схему полностью, отметьте комплект как неверсионированный. Не считайте локальный номер из чужой инструкции опубликованной версией этого сайта.

Деплой только сервера не меняет публичные гайды. Если серверное изменение затрагивает контракт агента, выпуск должен включать и клиентскую документацию.

5. Как читать блок изменения

id — стабильный идентификатор заметки; kind — added/changed/breaking/fixed/clarified; summary — наблюдаемое изменение; agentAction — что агент должен изменить в своей работе; documents — ссылки на подробные контракты. Заметка должна помещаться в несколько предложений. Это инструкция обновления, а не список коммитов и не рекламное описание функции.

Ниже — накопительный журнал. Первая запись фиксирует начальный комплект; возможности, описанные как существующие, не означают изменения runtime в этот день.

overlay-code-is-html (fixed)

Объект оверлея с html — полное определение (код), даже если в нём есть preset; пресет — только { "preset": "<id>" } без html. Что делать агенту: Не смешивайте preset и html в одном объекте: пресет — { "preset": "<id>" }, свой код — объект с html и правом «Эксперт».
